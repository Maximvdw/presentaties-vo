Introductie

  • Afname via Linked Data Event Streams (LDES)
    • Elke aangifte stroom heeft zijn eigen LDES (exploitatietoestanden en operationeel)
  • Elke aangifte (m.n. elke toestand) van de exploitatie is een Event binnen LDES
  • Linked data standaarden aangevuld met bijkomende concepten die hierop verder bouwen
  • We voorzien enkel data waarvan wij master zijn, voor de rest verwijzen (linken) we door naar de bron van de data
  • Voorlopig enkel een toelichting van het datamodel voor de structuur/exploitatietoestand

Codelijsten

De doelstelling van de codelijsten is om variabele businessvereisten af te splitsen van het stabiele datamodel en de applicatie.

  • Typering codelijsten: Geeft de (sub)typeringen aan van alle entiteiten binnen ons datamodel.
  • Eigenschappen codelijsten: Geeft de eigenschappen/attributen aan van alle entiteiten binnen ons datamodel waarvan de inhoud veranderlijk is per subtype.
  • Operationele codelijsten nog te bepalen

Codelijsten ...

  • onttrekkingspunt_type: pompput, opnamepunt, ...
  • emissiepunt_type: lozingspunt, ...
  • uitwisselpunt_type: geothermie, ...
  • meetpunt_type: peilput, meetinrichting, ...
  • meetinstrument_type: debietmeter, bi-directionele debietmeter, peillint, ...
  • ...

Codelijsten ...

  • meetpunt_eigenschappen:
    • voor het type peilput hebben we een eigenschap referentiepunt met invoerveld voor diepte en benaming
    • ...
  • onttrekkingspunt_eigenschappen:
    • voor het type pompput hebben we een eigenschap diepte met invoerveld voor diepte
    • voor het type pompput hebben we een eigenschap waterlaag dat refereert naar een andere codelijst (selectie)
    • ...

Toestand

Een exploitatietoestand bestaat uit;

  • ... een unieke identifier van de exploitatie
  • ... de datum waarop de (nieuwe) toestand actief is
  • ... de datum waarop de (nieuwe) toestand ingediend is

Inhoud vs Samenhang

Inhoudelijk data gaat over de emissiepunten, installaties, ... en de gegevens die hieraan gekoppeld zijn.
