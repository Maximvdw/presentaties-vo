The Developer Gap

Despite growing adoption of linked open data, ontology engineers and software teams speak different languages.

OWL/RDF-based data models are often too abstract for developers to implement against directly.

The challenge

Documentation and traceability help—but keeping them aligned with a continuously evolving ontology and codebase is unsustainable manually.

ODDToolkit

An extensible open-source toolkit that generates implementation artefacts from an OWL ontology enriched with a SKOS concept scheme.

flowchart LR OWL[("OWL Ontology")] SKOS[("SKOS Concept Scheme")] CONFIG["⚙️ Config Rules"] PIPELINE("ODDToolkit Pipeline") ARTEFACTS["📦 Artefacts"] OWL --> PIPELINE SKOS --> PIPELINE CONFIG --> PIPELINE PIPELINE --> ARTEFACTS

SKOS naming bridge

A SKOS concept scheme acts as an explicit naming bridge: ontology predicates are projected to developer-friendly identifiers without modifying the ontology itself.

Generated Artefacts

  • Visual UML class and ER diagrams
  • SQL schemas
  • Java and TypeScript models
  • SHACL shapes
  • JSON-LD frames
  • Bikeshed specification documents

Real-World Use Case

Demonstrated using a real-world industrial emissions ontology for environmental reporting (Flemish Government).

ODDToolkit generated documentation and implementation artefacts for development teams, integrated into CI workflows.

Conclusion & Future Work

  • ODDToolkit closes the gap between ontology engineers and developers
  • CI integration keeps artefacts synchronised with the ontology
  • Future: additional generators, richer SKOS mapping rules, community plugins
